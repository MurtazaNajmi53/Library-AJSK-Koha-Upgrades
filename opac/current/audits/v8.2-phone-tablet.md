# OPAC v8.2: phone and tablet audit

13 Nov 2026. The v8.2 masters were swapped into the live catalogue and shown in same-origin frames at the widths below. The Chrome window itself couldn't be resized, so touch emulation wasn't available: `(hover: none)` paths were checked by reading the CSS, not by tapping.

Skills used: `design-skills:design-critique` and `hzblj-skills:ui-surfaces`.

| Screen | 390 | 900 (tablet) | 1300 | RTL | Notes |
|---|---|---|---|---|---|
| Results rows | Pass | Pass | Pass | Pass (1366) | Titles take the full width. Click & Collect is full width, with cart and ⋯ under it. No sideways page scroll (scroll width 375 at 390) |
| Select titles | Bar scrolls sideways to reach it | Pass | Pass | Pass | Accepted: a rare task |
| ⋯ row menu | Pass | Pass | Pass | Pass | Placed against the window, so it is never clipped. It opens upwards near the bottom edge |
| Record page | Pass | n/a | Pass | Not checked | Actions sit under the title and author, inside the first screen. The breadcrumb is hidden on phones |
| Holdings | Cards | Grid | Grid | Not checked | No horizontal scroll |
| Cart pull-out | Not checked | n/a | Pass | Not checked | The menu opens upwards from its start edge, inside the drawer |
| Click & Collect dialog | Bottom sheet, pass | n/a | Card, pass | Logical padding | Confirm sits in thumb reach. Dates are 2 across, 1 across under 360px |
| New arrivals popup | Pass | n/a | Pass (900 and 740 high) | Pass | Close button and next arrow are equal. Long shelf names wrap under their icon |

Not covered: 360×740, 768×1024, 820×1180 and 1024×768 one by one (the tablet check was at 900px), and a real touch device. The 360px and 1024px boundaries are set in CSS (`max-width: 359.98px`, `1023.98px`). Worth a pass on a real phone or tablet before installing.
