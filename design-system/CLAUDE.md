# Maktabat Aljamea design system

This folder is the repo copy of the **Maktabat Aljamea** design system. It covers anything that carries the library's name: the Koha OPAC and self-checkout, staff-facing notices, email, printed covers and teaching slides.

Read [README.md](README.md) first. It is the brand book (tone, colour, type, shape, motion, accessibility, iconography) and it overrides anything here that seems to conflict with it.

The live, editable original is a claude.ai design-system artifact: https://claude.ai/artifact/5a6SFupnh2i2ytpyDFxBmU. This folder was exported from it on 10 November 2026 (artifact version `1794301098-6717`). See "Keeping the two copies in step" below.

## Working on it

```bash
node design-system/scripts/build.mjs          # after any change to tokens.json or a preview's @dsCard line
node design-system/scripts/build.mjs --check  # exits 1 if tokens.css is stale (use before committing)
python3 -m http.server 8000 --directory design-system   # then open http://localhost:8000/gallery.html
```

Before you commit a design-system change: run the build, open the gallery, and look at what you touched in **light and dark** and in **LTR and RTL**.

### Changing a token

1. Edit `tokens.json`. Families other than `type` are lists: `{"tokens": [{"name", "value", "usage"}]}`. Never convert them to a name→value map (DTCG style). The artifact can't read that shape.
2. Colour values are hex, `rgb()/rgba()/hsl()/oklch()`, or an alias `"{other-token}"` of a colour token that exists. No named colours (`red`, `transparent`, `currentColor`), no `var()`, no `color-mix()`.
3. Themed tokens give a value per theme: `{"light": "…", "dark": "…"}`. A missing dark value falls back to light.
4. Every token needs a `usage` note. Names are unique across all families: `[A-Za-z0-9][A-Za-z0-9_.-]*`.
5. Rebuild, then check contrast (below) in both themes.

### Changing or adding a component

- Style it in `components/bundle.css` with semantic tokens only. Never use a palette token (`copper-600`, `navy-900`) or a raw hex value in a component.
- Wrap markup in `.aj` and prefix classes `aj-`. Behaviour goes in `bundle.js` as a helper on `window.Aljamea`, wired by `Aljamea.init()`. Plain ES5-style classic script: no imports, no network, no dependencies, and never the literal `</script` (Koha inlines it).
- New component: add `components/<Name>/README.md` and `components/<Name>/preview.html` (with the `@dsCard` line), add its name to the Components list at the end of `README.md`, rebuild.

## Rules that must hold

These come from the brand book. Check every change against them.

**Colour.** Two tiers. Palette tokens are raw brand values and never change between themes. Semantic tokens (`surface-*`, `text-*`, `action*`, `border-*`, `focus-ring`, `ornament`, `logo`) name a job and point at a palette token per theme. Components use semantic tokens only. `ornament` (copper on cream, 2.75:1) is decoration only, never text and never the only cue for a state. Copper text on `surface-band` uses `text-accent`, not `action`.

**Accessibility floor.** Text is 4.5:1 or better on every surface it sits on, in both themes (3:1 at 24px+, and for control borders, focus rings and icons). Targets are at least 44px. Focus is a 3px solid `focus-ring` with 2px offset, never removed. Menus, tabs and the shelf work from the keyboard. Status is never shown by colour alone. Forms have visible labels and linked errors. If a change breaks one of these, flag it rather than ship it.

**Type.** One Latin family, DM Sans, in two roles: `display` (headings, navigation, record titles; 600–700 with negative tracking) and `ui` (body, buttons, labels). Arabic uses Tajawal for UI and headings. Amiri is only for Quran, hadith and iqtibasaat passages. Kanz-al-Marjaan is only for Arabic and LSD titles and authors in search results. **Never set LSD in Tajawal.** It lacks 23 LSD letters. Tajawal has no 600 weight: use 500 for labels and menus, 700 for headings and buttons. Smallest text is 13px Latin, 14px Arabic. Running text stops at 68ch.

**Direction.** Arabic and LSD pages set `dir="rtl" lang="ar"`. Use logical properties (`inline-start`, `margin-inline-end`) so layout mirrors by itself. Directional icons mirror with `.aj-flip`. Logos, the rosette and numbers never do.

**Content.** Plain, direct English. Sentence case everywhere except the library's name. Buttons name the outcome ("Place hold"), and confirmations repeat it ("Hold placed"). Never "Submit", never "→" after a label. Errors say what happened and what to do, without apology. No uppercase eyebrows, no "A · B · C" metadata strings, no emoji, no exclamation marks. Titles of honour follow the name in capitals with no full stops (Syedna TUS, Imam Husain AS, Rasul Allah SAW), and the possessive sits on the name ("Rasul Allah's SAW"). LSD words (zikr, waʿz, raza) are italic. Names of people, places and books are not.

**Motion.** Motion shows what changed after the reader acts. It is never decoration. Enter with `ease-out`, leave with `ease-in`, and leave faster than you arrive. Animate `transform` and `opacity`, and name each transitioned property (no `transition: all`). Under `prefers-reduced-motion`, movement drops to zero and fades shorten to `duration-instant`, but state still changes visibly.

**Imagery.** The rosette is the only ornament: covers, the loader, empty states, the footer and feature-card watermarks (one watermark per page) and the event date ring. Cards have no top rule. Records without an image get the generated BookCover, never a stock photo. Never approximate the logo: use `.aj-logo` on screen (it masks the real artwork in the `logo` token) and the files in `assets/` everywhere else.

## Applying it to Koha

The live OPAC files are in `../opac/current/` (see `../opac/current/INSTALL.md` for what is pasted where). They predate these tokens and still use the `--aj-*` custom properties. When moving OPAC code onto the system, use the migration table in `README.md` ("Moving from the OPAC stylesheet"). For example, `--aj-copper-deep` becomes `--action` and `--aj-sand` becomes `--surface-band`.

Koha prints OPACUserCSS and OPACUserJS inline on every page. So:

- Put `tokens.css` and `components/bundle.css` in OPACUserCSS, and `components/bundle.js` (then `Aljamea.init()`) in OPACUserJS. Strip comments for the paste copies the way `../opac/current/build.js` does.
- Fonts can't be loaded by relative path from a system preference. Host the `fonts/` files somewhere the OPAC can reach and rewrite the `@font-face` URLs in the pasted copy. Don't edit `tokens.css` here to do it.
- The logo is already inlined as a data URI in `bundle.css` (`.aj-logo`), because masks need CORS.

## Keeping the two copies in step

The artifact and this folder can drift. Pick one as the place you edit and copy the other way deliberately.

- **Repo → artifact:** publish the changed files back to the artifact URL under their `project/<path>` names (for example `tokens.json` → `project/tokens.json`). Don't send `tokens.css` or `components/index.json`, which the artifact generates. Send `design-system.json` last, and only if its title or asset records changed. Assets in `assets/Brand`, `assets/Print` and the Email PNGs are uploads in the artifact, so a changed image is uploaded as an asset and its record updated in `design-system.json`.
- **Artifact → repo:** read the changed `project/` files from the artifact and copy them over the matching paths here, then rebuild. In `components/BookCover/preview.html` and `components/EmailTemplate/preview.html`, the artifact uses `/_blob/<id>` URLs for images. This copy rewrites them to `../../assets/…` paths, so re-apply that rewrite.

## Known gaps (as exported)

- `assets/Brand/aljamea-logo-cream.svg` is byte-for-byte the same file as `aljamea-logo.svg`. Its paths also carry a class (`st0`) with no style, so through `<img>` it renders black, not blue or cream. On screen this doesn't matter, because `.aj-logo` masks it. For print or email, get the original blue and cream SVGs and replace both.
- `tokens.json` defines a type style `h3` twice: Display, 1.25rem/600, and Text, 1.125rem/700. The build keeps the first and warns. Decide which one is right and rename or remove the other.
- `README.md` mentions Facets and Toolbar components, but there are no folders for them. FilterDrawer and the results toolbar inside ResultsPage cover that ground.
- `assets/Source/OPACUserCSS_V4.paste.css` is a snapshot. If the OPAC stylesheet in `../opac/current/` changes, that one wins.
